Mix Pi Performance Plan

What we measured on the Pi today, what makes playback lag or cut out, and the changes in the order I would make them. Every number below comes from the live rig, playing two decks from the SD card.

Live now

Mixxx draws on the graphics chip. It was drawing every waveform on the CPU. With two decks playing, Mixxx went from 120% to 36% of a core and the Pi runs about 3 °C cooler. One file turns it on; deleting it turns it off.

Diagnosis

Why playback lags or cuts out

Ranked by how likely each one is to cause what you hear at a set. The SD card held up under every test, so the remaining suspects sit around USB.

Fixed live

Waveforms drawn on the CPU

Raspberry Pi's build of Sway points apps at the display chip, which cannot draw, so Mixxx fell back to software drawing. The interface thread and four drawing threads took about 1.1 cores. That is the screen and controller lag. Fixed by pointing Sway at the 3D chip.

Test next

Slow reads from the USB stick

Mixxx keeps only 0.37 s of each track read ahead. If the stick pauses longer, that deck goes silent while everything else keeps running. The stick shares a USB 2 hub with the Starlight, and at the gig the hub had no power of its own. Not tested yet: the stick was not plugged in.

Known

Tracks that fail to decode

Four MANTACORE tracks failed in earlier logs: Jealousy, TAMALE, Morning Dew (Donk) and Lady. Mixxx stops reading them partway and the deck goes silent. All 19 MP3s on the SD card check out as real MP3s.

Watch

One slow audio cycle per session

Audio cycles usually take 1.2 ms. The slowest took 35–43 ms against 46 ms of buffer. It also happened with nothing playing, so it is most likely a one-off at start-up. Confirming that needs a per-cycle trace.

Ruled out

SD card stalls and RAM

Zero missed reads with the disk 43% busy writing. Memory never ran short. Adding RAM would not change anything.

1

Settings

About 10 minutes on the Pi. No rebuild. Each one undoes in seconds.

Keep the graphics-chip fix and add it to the image

LiveImage: not yet

Mixxx 120% → 36% of a core. Already on the Pi in /etc/X11/Xsession.d/80mixpi-gpu-render-node. A fresh card will not have it until the build adds the same file.

Undo: delete that file and restart the session.

Key lock engine: RubberBand → SoundTouch

Ear test

Halves the audio thread, 12.8% → 5.9%. More headroom against dropouts. Only switch if it doesn't sound worse: take the blind Key Lock Ear Test, two sets of two songs at −8% and +8%, rendered with the same libraries Mixxx uses on the Pi.

Undo: switch it back in the ⚙ panel or Preferences.

Waveforms stay at 60 fps

Decided

You chose smooth scrolling. With the graphics chip on, 60 fps already costs far less than before (interface thread 41% → 18%), so no change.

Hide iTunes, Traktor, Serato, Rhythmbox and Banshee

DecidedStage 3

Done as a Sources menu you can tick, not a one-off setting. See stage 3.

SD write cap, only if needed

On hold

USB copying stays as it is, since it never runs during a set. The writes that do happen mid-set are small: Mixxx saving analysis when you load a never-analysed track, recordings (about 10 MB a minute), and play-count updates. The tests wrote 1.2 GB during playback with no effect, so this waits unless recording mid-set causes hiccups.

Pause maintenance during sets

AgreedBuilding

Stop the apt updates, man-db, log rotation, fstrim, disk checks and swap write-back timers while Mixxx is open. A small helper remembers which timers were on, stops them when Mixxx starts and restores them when it closes. It never interrupts an update that is already running.

Audio buffer: 11.6 ms looks safe, 5.8 ms is possible

Tested

Two decks playing plus a 600 MB SD write, 75 s at each size: 23 ms, 11.6 ms and 5.8 ms all ran with zero underruns. The buffer never got past 58% full. Smaller buffers cost audio-thread CPU: 12.8% at 23 ms, 14.9% at 11.6 ms, 19.1% at 5.8 ms. Next: a 30-minute set at 11.6 ms with the controller, effects and track loads before making it the default. Changing it restarts audio for a moment, so it goes in the ⚙ panel behind a confirm, for use between tracks.

2

USB playback

The main suspect for audio cutting out. Test first, then fix what the test shows.

Run the same test from the USB stick

Needs MANTACORE

Plug the stick in and I play both decks from it with Mixxx's diagnostic mode on. When Mixxx closes it reports how many reads came back too late and how slow the worst audio cycle was. Then repeat with the hub on its own power.

Plug sticks into a blue USB 3 port on the Pi

Free

Today the Starlight sits on the USB 2 hub. The blue ports run on a separate bus, so the stick and the controller stop sharing bandwidth.

Power the Pi from its own supply

RecommendedHardware

Today the Pi takes its power from a hub port. A Pi 4 needs 5.1 V at 3 A, and it also feeds the screen, the Starlight, the USB stick and soon the fans. Hub ports usually give 2–2.4 A, and the voltage sags through the hub and cable. Below 4.63 V the Pi drops USB devices, which matches the gig cut-outs. Use the official 5.1 V 3 A USB-C supply straight into the Pi and keep the hub on its own adapter. For one cable into the box, put a two-socket strip inside. No undervoltage has been logged since 6 November, but the Pi was mostly idle.

Copy the night's crate to the SD card

Works today

The SD card played clean in every test, including under heavy load. USB ⇄ Pi already copies and verifies a Rekordbox export.

Read further ahead: 0.37 s and up

AgreedBuilding

Built as a setting, not a fixed number, so we can step it up (0.37 s, then 1.5 s, then several seconds) and find how far it goes. Mixxx holds 80 chunks, about 15 s, per deck; that is the ceiling. Tested first with simulated USB stalls on the Pi, then with MANTACORE.

Keep loaded tracks in RAM, like a CDJ

Building

When a track loads from a stick or card, Mixxx copies the file into RAM and plays the copy. The deck keeps playing after you eject, and a stalling stick can no longer cut the audio. A FLAC is about 25–50 MB and 3 GB is free. Loading from USB 2 takes a second or two longer.

Fix the four tracks that fail to decode

Library

Re-export them from Rekordbox or convert them. Until then, they can cut out mid-track on any setup.

Keep the detailed waveforms

Decided

Today's colour-by-frequency waveforms stay, at 60 fps. The simple bars in the sketch were only a placeholder.

Tabs: Perform, Browse, FX

Skin

Tapping the open tab does nothing. Today it switches you away, which is easy to hit by mistake mid-set.

One media LOAD and EJECT, not one per deck

Decided

Sticks and cards connect to the Pi, not to a deck, so the Perform view gets one media slot. LOAD opens the stick's Rekordbox library in Browse. EJECT is press-and-hold. Loading tracks into decks stays in Browse and on the Starlight. See stage 4.

REC button and a CPU lamp

Skin

Recording starts without opening Browse. The lamp shows how hard the audio engine is working and turns red on an overload.

Beat FX on its own tab, with two bugs fixed

AgreedFixing

A typo in the skin means Beat FX probably reaches Deck 1 only. Switching an effect on also jumps it straight to full depth.

Sources menu: tick which sources the sidebar shows

DecidedMixxx patch

Works like the column menu, with a tap instead of a right-click. A Sources button at the top of the Browse sidebar opens a list with tick boxes for every source: Tracks, Auto DJ, Playlists, Crates, Computer, Recordings, History, Rekordbox, iTunes, Traktor, Serato, Rhythmbox, Banshee. Unticking hides it straight away. iTunes, Traktor, Serato, Rhythmbox and Banshee are then also skipped at start-up. The same list appears on the touch settings page. Dragging to re-order, as with columns, comes next. The same menu sets the default source that Browse opens to (Rekordbox for you), and can limit the library view to one source, several or all.

⚙ panel for settings that change live

Agreed

Key lock engine, waveform speed, tempo range, quantize, sync, split cue and the audio buffer, without leaving the decks. The audio buffer asks first, because audio restarts for a moment. The controller and waveform type move to a touch page that applies them only when no track is loaded.

Smaller fixes

Skin

48 px buttons instead of 30 px, the track number field fixed, samplers cut from 16 to 8, and stop or cue on a sample by tap instead of right-click.

Eject asks for a second tap

Top bar

A CDJ makes you hold USB STOP until the light stops blinking. The top bar has no long press, so a second tap within three seconds confirms.

Decks keep playing after eject

AgreedBuilding

Loaded tracks are held in RAM (stage 2), so eject goes ahead while a deck plays and the music carries on, as on a CDJ. Eject only waits while a track from that stick is still loading or being analysed, and names it. Then it unmounts, powers the stick off and the chip turns grey: safe to pull.

Rekordbox first, chosen in the Sources menu

Decided

You default to the Rekordbox source, so Browse opens on the inserted stick's Rekordbox playlists, like a CDJ. The Sources menu sets that default and can limit the library view to one source, several or all. Copying a night's crate to the Pi stays available.

Phase 2: the media slot inside Mixxx

Planned

A Mixxx change adds media-slot controls that both the skin and the Starlight can use. The Perform view shows the stick's name with a status light: green ready, blinking amber ejecting, grey remove, red busy. LOAD opens its Rekordbox playlists. EJECT becomes a true press-and-hold like USB STOP, because Mixxx can time the hold. A controller button can be mapped to eject. Mixxx knows which deck plays which file, so the in-use check is exact. It is about 400–600 lines of C++ to carry through upgrades. Phase 1, the top-bar chip, works without changing Mixxx.

6

Versions & hardware

What to pull in from Mixxx, and when new hardware is worth it.

Stay on Mixxx 2.5.6

Now

Still the latest stable release. 2.6 has been in beta since May 2025, and 2.7 is in development; its new interface isn't touch-ready.

Pull in three upstream fixes

Rebuild

Hidden .PIONEER folders on sticks (#16895), clean shutdown of analysis (#16064) and the Starlight filter superknob (#14126).

Try 2.6 on a spare card later

Later

It has a GLES build option and a lighter RubberBand mode. Our two patches would need rewriting, and the skins are untested on it. Upstream's fix for library freezes on slow storage is still unmerged (#17213).

Two fans in the box

In progress

Small fan over the main chip, big fan as a high exhaust with a low intake vent. The fan model has its own thread. Today's fixes already took the load temperature from 67 to 61 °C.

Pi 5 with 4 GB and an SSD

Bolder path

Roughly 2–3× the CPU and graphics, a built-in fan header and fast storage. It needs a 5 V 5 A supply and a 22-to-15-pin display cable. Same software stack, so the plan above carries over.
